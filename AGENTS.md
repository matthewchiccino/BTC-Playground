# AGENTS.md

Guide for AI coding agents (and humans) working in this repo. Claude Code reads
it through [`CLAUDE.md`](CLAUDE.md); other tools read it directly. Keep it
short: if a rule can be a test, make it a test instead (see
[`docs/agentic-development.md`](docs/agentic-development.md)).

## What this is

BTC Playground builds deliberately invalid Bitcoin blocks/transactions, submits
them to a **real regtest `bitcoind` (v31.1)**, and shows the node's verbatim
rejection string next to the exact Bitcoin Core C++ line that produced it.
FastAPI backend, React/Vite frontend, one shared node, no database, no auth.

## Commands (use these, not ad-hoc equivalents)

| Do this | Command | Needs |
|---|---|---|
| See everything | `make help` | |
| **Fast loop, run constantly** | `make test` | nothing (~1s) |
| Pre-commit gate (lint + build + unit) | `make check` | deps installed (`make setup`) |
| Scenario verdicts + exact boundaries | `make test-integration` | running node (`make node`) |
| Cited Core lines still real | `make test-sources` | internet |
| Run the app | `make dev` | node tools installed |

CI runs exactly these (`.github/workflows/ci.yml`). Green locally means green in CI. A push to `main` that passes CI **deploys to production** automatically, so pushing is shipping.

## Repo map

- `backend/scenarios.py`: **the catalog** (data). `mutations.py`: one builder per scenario. `sources.py`: rejection string → C++ source citation.
- `backend/main.py`: API (`/build`, `/submit`, `/scenarios`, `/health`, `/node-*`, `/mainnet-blocks`). `buildcache.py`, `ratelimit.py`, `decode.py`, `node.py`: small, single-purpose. `livechain.py` is display-only mainnet data from a public explorer, **not our node**; never let it feed a scenario.
- `backend/vendor/test_framework/`: **Bitcoin Core's own code, vendored verbatim. Do not edit.** Vendor a missing dependency instead (`VENDORED.md`).
- `backend/tests/{unit,integration,network}/`: tiers by what they need. `frontend/src/`: React UI (`App.jsx` is the orchestrator).
- `docs/`: architecture, playbooks, ADRs. `ROADMAP.md`: what's next.

## Boundaries

**Always**
- Run `make check` before calling a change done; run the matching tier for what you touched (below).
- Verify claims about Bitcoin Core against the **live node** and the **pinned source**, never from memory (see next section).
- Keep changes small and scoped; add or update tests with the code.

**Ask first**
- Changing `COMMIT` in `sources.py` or the bitcoind version (they must move together with `Dockerfile`, CI's `BITCOIN_VERSION`, `VENDORED.md`).
- Anything in `Dockerfile`, `fly.toml`, `Caddyfile`, `entrypoint.sh` (deployment).
- `make reset-chain`, adding a dependency, or loosening a constraint recorded in `docs/decisions/`.
- Committing or pushing (only when the user asks).

**Never**
- Edit `backend/vendor/`, commit `fixtures.json` / `node_debug.log` / credentials, or add a database, auth, or a state-changing RPC to `/submit` (see ADR 0001).
- Mine on the frozen chain at serve time, or "fix" a failing test by loosening it: find out why it fails.

## Bitcoin facts: provenance rule

This project's whole value is that its claims are true. So:
- A rejection string, line number, or "consensus vs policy" statement is written only after you **triggered it on the live node** and **read the pinned source**.
- Policy vs consensus matters: if a rule is mempool-only (`dust`, `min relay fee not met`), say so; a miner could still mine that tx.
- `make test-sources` proves a citation's line range contains its string; it does not prove the *right* call site. `python3 backend/gen_sources.py scan && diff` finds other sites for the same string. The `dust` entry in `sources.py` was originally cited wrong for this reason.

## Conventions

- **Add a scenario:** follow [`docs/adding-a-scenario.md`](docs/adding-a-scenario.md). It is one catalog entry + one mutation (+ source entry + boundary row). `tests/unit/test_catalog.py` fails with an instruction if you miss a piece. Do not hardcode scenario ids in `App.jsx`; hints and inputs come from the catalog.
- Comments explain *why* (constraints, surprising Core behavior), not *what*. Match the surrounding density.
- Commits: imperative summary, body explains why. One logical change each.
- Backend targets Python 3.12 (the Docker image); local dev may be newer.

## Gotchas

- `backend/fixtures.json` is generated by `make node` and gitignored. Unit tests never need it (`tests/conftest.py` stubs it); integration tests do.
- Each mutation rebuilds against the live node, so integration needs the node up. If it died (`pgrep bitcoind` empty), check the tail of `node_debug.log`, then `./scripts/start_node.sh`. On this macOS setup the node has twice been killed by `Operation not permitted` on its own datadir; a restart restores the frozen chain.
- Ports: backend 8000, frontend 5173, regtest RPC 18443.
- `docs/history/` and `docs/explainer.md` are dated; trust `AGENTS.md`, `docs/architecture.md`, and `docs/decisions/` first.

## When you're stuck or the spec is open

Say what you know, what you don't, and ask. The original build plan used explicit
**DECIDE** gates for exactly this: an agent inventing an answer to an open design
question is worse than an agent that stops. Open questions live in
[`ROADMAP.md`](ROADMAP.md#open-decisions-for-a-human).
